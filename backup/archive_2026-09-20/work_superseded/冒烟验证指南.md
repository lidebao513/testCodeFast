# 冒烟验证操作指南 · research-agent 本地测试

## 一、平台状态
- 测试加速平台已在 **http://localhost:8000** 持续运行（FastAPI，后台任务）。
- 冒烟接口（research-agent 项目 id=2，部署地址 http://localhost:8010）：
  - `GET  /api/projects/2/smoke` —— 匿名冒烟（不登录）
  - `POST /api/projects/2/smoke` —— 登录冒烟（body 带 `account` / `password`）
- 也可传 `?base_url=` 或 body 里的 `base_url` 覆盖地址（如你用其他端口启动被测服务）。

## 二、第一步：本地启动 research-agent（你来执行）
research-agent 后端 `server.py` 写死 `port=8000`，与平台冲突，**必须用 8010 启动**：

方式 A（推荐，不动被测代码）：
```bash
cd <research-agent>/backend/research-agent-source
python -m uvicorn server:app --host 0.0.0.0 --port 8010
```
方式 B（改代码）：把 `server.py` 约第 6197 行 `uvicorn.run(..., port=8000)` 改为 `port=8010`，再 `python server.py`。

前置依赖（需你本地已就绪）：MySQL8 + ChromaDB + LLM 环境变量（research-agent 内部读 `OPENAI_BASE_URL` 等）。

## 三、第二步：冒烟验证（我来跑 / 你也可自验）
```bash
# 匿名：确认服务已启动、health/login/鉴权链路可用
curl http://localhost:8000/api/projects/2/smoke

# 登录：提供账号密码，确认登录态与受保护接口可用
curl -X POST http://localhost:8000/api/projects/2/smoke \
  -H 'Content-Type: application/json' \
  -d '{"account":"你的账号","password":"你的密码"}'
```

## 四、判定含义
| verdict | 含义 | 处置 |
|---|---|---|
| `UNREACHABLE` | 8010 无服务 / 地址或端口错 | 确认 research-agent 已起在 8010 |
| `SERVICE_UP` | 服务已起，匿名探活通过 | 可做下一步；给账号密码做登录验证 |
| `READY` | 登录态可用，受保护接口可访问 | 完全就绪，可做真实测试 |
| `AUTH_FAIL` | 服务起但登录失败 | 检查账号密码 / 登录端点路径 |

## 附：已定位并解决的坑
1. **系统 HTTP 代理**导致 localhost 探活返回 502/超时 → 冒烟请求强制 `proxies=None` + `trust_env=False`，且平台启动脚本 `start_platform.sh` 固化 `unset` 代理环境变量。
2. **localhost 解析走 IPv6(::1)** 导致探测延迟 → 冒烟内统一把 `localhost` 替换为 `127.0.0.1` 直连。
3. research-agent 真实路由（已核对源码）：`GET /api/v1/health`（公开）、`POST /api/v1/auth/unified-login`（account+password）、`POST /api/v1/auth/login`（username+password）、`GET /api/v1/threads`、`GET /api/v1/projects`（需 Bearer）。
