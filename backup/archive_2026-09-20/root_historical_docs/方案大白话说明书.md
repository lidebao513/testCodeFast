# 方案大白话说明书

> 这份文件把《代码转测试用例_方案整合版.md》里所有的专业术语，翻译成日常语言。
> 不需要任何技术背景，从头读到尾就能明白：**我们要干什么、我推荐怎么干、每一步在干什么、你要决定哪 6 件事、以及现在只需做什么。**
> 最后一章附「术语 ↔ 人话」对照表，以后再看到那些词可以回来查。

---

## 一、大白话：我们到底要干什么？

**现在的情况**

你手上有一个自己攒的小工具。它的作用是：给它一份代码，它自动告诉你"这份代码该测哪些点、每个点该怎么测"。

它**能跑**，但生成出来的东西**质量一般**——很像套模板，写不出那种"老测试一看就知道是懂行的人写的"用例。

**你想要的**

1. 让它变成一个**正经的服务**：把代码交进去，它规规矩矩吐出一整套测试用例。
2. 能**装在你自己的电脑或公司内网里**，代码和资料不出门（安全）。
3. 它看代码的时候**只能看、不能改**（防止把别人的代码搞坏）。
4. 生成质量要**明显上一个台阶**，最好还能一眼看出"这条用例是根据哪一行代码想出来的"。

**打个比方**

现在的工具像**你会做菜、但只有一个电磁炉**；你要的是**一间正经厨房**——灶台、抽油烟机、刀具都齐，谁来了都能干活。

---

## 二、三条路，用"家"来打比方

要达成上面那些目标，有三条路可以走。我用装修打比方，你一眼就能看出区别。

| | 像什么 | 好处（大白话） | 坏处（大白话） | 什么时候该选它 |
|---|---|---|---|---|
| **① 原地开发** | **老房子翻新** | 不搬家、老家具全留着、马上能动工 | 承重墙动不了，格局改不大；翻新期间家里一团乱 | 你只有一个人、时间又紧、不想同时伺候两套房 |
| **② 新建独立服务**（我最推荐） | **盖一栋新房，把老房里好用的家具搬过去** | 格局随便定，天生就是"正经房子"；质量上限最高；以后能当独立服务对外 | 要搬家、要花力气，初期最费工 | 你**已经明确要把它做成对外的服务** |
| **③ 买现成工具**（DeepSeek Harness 这类） | **买一台做好的"工具机"**（但要能搬进自己家、不通公网） | 开箱即用、上手快、本地能跑、还免费开源 | 它只"照着你的稿子抄"，不会帮你"补该写却没写的"；产出格式跟你的规矩对不上，还得人改 | 想**快速试试 AI 到底行不行**，或临时赶一批用例 |

> 一句话总结：**① 是修房，② 是盖房，③ 是买机器。**
> 机器再好也替代不了房子——所以 ③ 不适合当"家"，只适合当"家里的一台设备"。

---

## 三、我推荐怎么走（一句话）

> **盖新房（②）**，但把老房里所有好用的家具**整套搬过去**（不重做、不浪费）；
> 另外买的那台"工具机"（③）**不当房子用，只当成一个可以外挂的"聪明大脑"**——先让它试工，干得好才留下，干不好就当没买。
> 老房子**原样保留**，随时能搬回去住。

---

## 四、为什么这么推荐（4 条大白话理由）

1. **你要的"能自己装、又能当服务、又能当工具用"，只有盖新房这条路天生满足。**
   修房（①）只是"顺带多盖一间"，买机器（③）根本不是房子。

2. **你要的"只看不改、整份扫描、全量+增量用例"，这些你其实已经有了。**
   只是它们现在住在老房子里，**搬家就行，不用重新造**——重新造纯属浪费。

3. **质量要上一个台阶，就必须让"聪明的工匠（AI）来写、老师傅（规则）来把关"。**
   这是我推荐那套新房子的"天然结构"：AI 负责写得好，规则负责保证"不许瞎编"。
   现在的老工具是"纯纯套模板"，所以才有一股模板味。

4. **万一搞砸了，随时能撤。**
   老工具一直原封不动留着，新房子没住顺就搬回来，**不存在"推倒重来回不去"的风险**。

## 五、整个过程分几步走（还是用搬家打比方）

我把整个工程拆成 6 步。**每一步都能单独完工、单独验收，你不用一口气全做。**

### 第一步 · 拍照存证（备份）——**零风险，先做这个**

- **干什么**：把现在的项目和数据库**完整拍个快照**存档（相当于搬家前给老房每个角落拍照、把老家具编号）。
- **为什么先做**：万一后面哪里出了岔子，随时能恢复到今天这个状态。
- **做完你能看到**：一个可以随时还原的存档点。**这一步谁都改不坏东西。**

### 第二步 · 清点家具 + 定好规矩（纯文档，不动代码）

- **干什么**：
  - **清点**：把老工具里的东西一件件列出来，标明每件是"**直接搬走继续用**"、"**修一修搬走**"、"**扔掉重买**"还是"**不要了**"。
  - **定规矩**：让新系统跟老系统"说同样的话"——以后不管谁换谁，说的格式都一样，不会乱套。
- **为什么重要**：这一步能保证新家跟老家的东西**能对接上**，将来换回来也顺。
- **做完你能看到**：两张表——"家具清单"和"说话规矩"。

### 第三步 · 盖房子的架子（先盖空房）

- **干什么**：把新房子**框架搭起来**——能通电（能启动）、能通水（能访问）、能进门（有个首页）。
- **顺带干一件关键的事**：把"代码只能看不能改"这条规矩**做成房子自带的门锁**，从骨架阶段就焊死，而不是后期打补丁。
- **做完你能看到**：一个能启动的空服务，门口挂个牌子显示"我在正常运行"。

### 第四步 · 装核心机器（真正干活的部分）

- **干什么**：把最核心的三台机器装进新房：
  1. **读代码的机器**：看懂这份代码里有哪些功能、哪些接口。
  2. **"聪明大脑"（AI）**：负责把用例写得像老测试手写的。
  3. **"老师傅"（规则）**：负责**核对 AI 是不是在瞎编**——AI 提到的接口如果代码里根本不存在，就直接打回，不许出现在结果里。
- **这是质量跃升最关键的一步**，也是你说的"要摆脱模板感"落地的位置。

### 第五步 · 配齐全套 + 上双保险

- **干什么**：
  - **两种扫描模式**：既能"整份代码全扫"，也能"只扫这次改动的部分"（对应你要的**全量 / 增量**用例）。
  - **安全再加固**：代码只读、用完的工作区随手清理。
- **做完你能看到**：要全量给全量，要增量给增量；代码文件从头到尾一个字节都没被改过。

### 第六步 · 新旧并行试跑，好了再搬（挑一天换家）

- **干什么**：**新老两套同时跑同样的活**，把两份结果摆一起比。新的**不比老的差**，才正式切过去。
- **为什么这么做**：这样切换是"**先试住、后搬家**"，而不是"闭着眼跳"。
- **（可选加分项）**试那台"工具机"：把 DeepSeek Harness 拉进来跑几个真实模块，**干得好才装到新房当外挂大脑，干不好就当没买**，只借鉴它的思路。

> **每一步都留了"后悔药"**：随时能退回上一步，或者直接回老房子。

## 六、需要你拍板的 6 件事（每件都用大白话讲）

我下面把最让人头晕的 6 个决定，一个个翻译成"人话"。每条都给你我的建议和理由。

---

### 决定 1：走哪条路？

- **这在问什么**：修房（①）、盖房（②）、还是买机器（③）？
- **我的建议**：**盖房（②）**。
- **为什么**：因为你已经明确说了"目标是对外的独立服务"。修房满足不了这个；买机器根本不是房子。

---

### 决定 2：现在要不要先做"拍照存证"（第一步备份）？

- **这在问什么**：要不要现在就把当前状态存档？
- **我的建议**：**要，现在就做**。
- **为什么**：它**零风险**——只是复制一份存档，不改任何东西。却不做的话，后面万一出问题就回不到今天。**这是唯一一件建议你立刻点头的事。**

---

### 决定 3：那个"聪明大脑"从哪儿来？

- **这在问什么**：AI 用哪种方式接入？
  - **A：直接买云上的 AI 服务**（DeepSeek、通义千问这类，按用量付费）
  - **B：把 DeepSeek Harness 整套装进来用**
  - **C：两个都留着，随时切**
- **我的建议**：**先用 A，B 放到最后一步（第六步）当试用项**。
- **为什么**：A 最省事、今天就能通；B 还很新（官方自己标注"早期预览版、不建议上生产"），**先试用、验过再装**，不做小白鼠。

---

### 决定 4：要不要搞"代码完全不落地"的极致安全模式？

- **这在问什么**：要不要做一种"代码根本不在你电脑上存下来、只在远端扫一眼"的模式？
  - **A：所有项目都这样**
  - **B：只有涉密项目这样，普通项目正常本地只读**
  - **C：先不做**
- **我的建议**：**B（只有涉密项目才开）**。
- **为什么**：这种极致模式**确实更安全，但代价是又慢又容易撞上限流**（对方接口每小时调用有次数上限）。你要做的是"整份代码全扫"，全走远端反而划不来。**日常本地只读已经够安全；只有特别敏感的仓库才切过去。**

---

### 决定 5：要不要自己买显卡、训一个"专属模型"？

- **这在问什么**：要不要投入显卡资源，训一个只属于你们的模型？
- **我的建议**：**不买，先用云服务**。
- **为什么**：贵、费时间，而且**先得知道云服务到底差多少**。等第六步试完，如果发现"云服务就是不够好"，再考虑这件事也不迟。

---

### 决定 6：要不要现在就买"任务排队中间件"（Redis 那种）？

- **这在问什么**：任务一多怎么排队？
  - **A：先用简单方式（程序内存里排队）**
  - **B：现在就上专业的排队系统**
- **我的建议**：**先 A，压力大了再换 B**。
- **为什么**：现在活还没多到需要专业排队系统。**先跑起来看真实压力**，到时候再买不浪费。

---

## 七、你现在只需要做一件事

其余的都可以边走边定。**唯一建议你立刻回一句的，是"决定 2"：**

> **要不要现在先做备份（第一步）？**

- 回答"**要**" → 我就去做备份，**不碰任何代码逻辑，零风险**，做完给你看存档清单。
- 回答"**先不**" → 那就先停在这，方案文档已经都在，随时能启动。

**其他 5 个决定，等第一步做完、你手上有存档了，我们再一个个聊，不着急。**

## 八、术语 ↔ 人话 对照表

以后在方案里看到这些词，回来这张表查就行。

| 方案里的词 | 大白话 |
|---|---|
| **契约 / 数据契约** | "说话的规矩"——新旧系统约好字段名和格式，保证能互相对接 |
| **legacy（遗产/遗留）** | "老房子"——现有的旧工具旧代码，原样保留不动 |
| **冻结** | 把老系统"钉住不再改"，只当参照物 |
| **备份 / 快照 / tag** | "拍照存证"，随时能还原 |
| **黄金样本 / golden fixtures** | 挑几套"标准答案"存起来，用来比对新旧跑出来的结果 |
| **资产盘点** | "清点家具"，一件件标明搬走/修了搬/重买/扔掉 |
| **薄壳** | "空房子"——先把架子搭好，能启动能访问，里面还没装机器 |
| **引擎** | "干活的机器"——真正读代码、写用例的部分 |
| **规则引擎** | "老师傅"——靠死规矩把关，保证不瞎编、格式准 |
| **LLM / AI 引擎** | "聪明大脑"——负责把用例写得像人写的，补上遗漏的场景 |
| **双引擎** | 老师傅 + 聪明大脑配合：一个把关、一个发挥 |
| **防幻觉 / 校验层** | "打假环节"——AI 提到的东西如果在代码里查无实据，一律打回 |
| **证据引用** | 每条用例后面标注"我是根据哪一行代码想出来的" |
| **只读 / 只读工作区** | "只能看不能改"——代码进来就被上锁 |
| **全量 / 增量** | 全量=整份代码都扫；增量=只扫这次改动的部分 |
| **PoC（概念验证）** | "试用期"——先小范围试，行不行看结果说话 |
| **影子双跑** | "新旧同时跑一遍，结果并排比"，新的不差才切换 |
| **回滚 / 回滚点** | "后悔药"——出问题能退回上一步 |
| **零落盘** | "代码不在本地留任何痕迹"的极致安全模式 |
| **持久队列（Redis 那类）** | "专业的任务排队系统"，任务多了用它管理先后 |
| **微调模型** | "用你们自己的资料专门训一个模型"，更懂你们的业务 |
| **API** | "按次付费买云上的 AI 能力" |
| **门禁（quality gate）** | "出厂质检"——每次提交前自动检查一遍，不合格不许过 |

## 九、一句话收尾

> **我要做的**：把"套模板的小工具"升级成"能自己装、只看不改、AI 写+规则把关"的正经服务。
> **我推荐的走法**：盖新房（②）+ 搬老家具 + 外挂一台试用中的工具机（③），老房原样保留随时能回。
> **现在需要你的**：就回一句"备份要不要现在做"。
