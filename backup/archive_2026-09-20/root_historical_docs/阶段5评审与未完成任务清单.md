## 二、现状盘点

### 2.1 已具备（D-②6 落地后）
- **记录**：`runs`（batch_id / case_id / status / screenshot_path / log_path / duration_ms / created_at）、
  `reports`（batch_id / summary / html_path）；功能点/用例/测试点均有 `created_at`。
- **历史回溯**：`GET /runs?batch_id=`（精确回溯某轮）、`GET /batches`（每轮结果分布）、`GET /reports`。
- **实时进度**：`GET /execute/status`（registry 实时 + 进程重启后从 `runs` 表回退重建，`source` 标注）、
  `GET /execute/active`（进行中批次列表）。
- **可中断**：`POST /execute/cancel` + `ExecuteReq.async_mode`（后台线程启动、立即返回 batch_id 轮询）。
- **执行状态语义**（D-★1/★2 建立）：`pass` / `fail` / `structural_only` / `blocked_auth` / `error` / `skipped` / `blocked_review`。

### 2.2 名义存在、实质缺失
| 能力 | 现状缺口 |
|---|---|
| 对外回调 | 执行结束仅靠调用方主动轮询 `/execute/status`；无 webhook / 状态推送，流水线无法被通知 |
| 趋势看板 | 仅有 `/batches` 列表，无通过率/覆盖率趋势、无失败归因聚合页面 |
| 失败归因 | `runs` 只存 `status` 字符串，未区分「断言失败 / 环境失败 / 数据失败」 |
| status 口径 | `cases.status` 同时承载 `generated`/`pass`/`archived`(软删)/`blocked_review`，监控与趋势易混 |
| 进度持久化 | 进度注册表为进程内内存态，平台重启后"进行中活跃列表"清空（历史可由 runs 重建） |
| 截图/日志检索 | `runs.screenshot_path`/`log_path` 已写，但无按状态/批次聚合的检索入口 |

## 三、必须项（★）

### P5-★1　执行进度实时可见　✅ **已完成（D-②6，2026-09-09）**
进程内注册表 `done/total/percent/status_counts/state`；`GET /execute/status` 实时返回，未命中则回退 `runs` 表重建。

### P5-★2　执行可中断 / 取消　✅ **已完成（D-②6，2026-09-09）**
`_CANCEL_SET` 跨线程信号 + `POST /execute/cancel`；执行循环在 case / 分块（≤50 条）边界退出，已执行结果全部落库。

### P5-★3　执行历史可回溯与多轮对比　✅ **已完成（D-★5 + D-②6）**
`runs.batch_id` 贯穿执行与报告；`/runs?batch_id=`、`/batches`、`/execute/status` 回退，支撑多轮对比与 flaky 识别基础。

### P5-★4　执行异步任务化 + 完成回调（webhook / 状态推送）　✅ **已完成（阶段5 批次1，2026-09-09）**
**实现**：
- `async_mode` 后台线程执行结束后，按状态机终态（`done` / `cancelled` / `error`）**自动 POST** 配置的 webhook，
  payload 含 `event` / `project_id` / `project` / `batch_id` / `state` / `summary`（total+各状态分布）/
  `status_url`（进度查询入口）/ `finished_at`；best-effort，失败静默不阻塞主流程。
- webhook 地址来源：请求级 `ExecuteReq.webhook_url` 优先，缺省回退项目级 `projects.webhook_url`（db 已加列）。
- `executor.fire_webhook()` 独立 Session + `trust_env=False`，规避本机透明代理劫持 127.0.0.1 回调用流量。
- 新增 `GET /execute/tasks` 列出全部任务（含已结束），提供异步执行履历；`/execute` 响应新增 `tasks_url` 与 `webhook` 标记。
**自测**：`selftest_b5_2.py` B5-2-1/2/3 验证 webhook 回调 `state=done` / 取消后 `state=cancelled` / 无 webhook 不崩（11/11 通过）。
**剩余**：进程重启后"进行中"列表清空（注册表内存态）→ 属 P5-②5（进度持久化），非阻断。
