说明测试类型与执行时机

本章节为报告内置定义，说明本报告覆盖的测试类型及其执行时机；可随报告一起交付，也可在定稿时删除。
测试类型执行时机触发条件 / 说明
版本对比测试
Version Comparison		 多版本差异比对时 针对 git diff 命中的变更点（新增/修改/删除文件、路由、工具、接口）派生测试点，验证变更未引入回归、行为符合预期。典型触发：对比两个版本/分支/提交差异并评估影响面；CI“变更影响面测试”阶段。
全量测试
Full Regression		 发布前 / 重大变更后 对全量用例做回归执行，确保整体无回归，作为上线门禁（release gate）。典型触发：版本发布评审、大规模重构 / 底层依赖升级、生产环境上线前。
新增功能覆盖测试
New Feature Coverage		 迭代新增功能时 针对本次增量提交中新增/修改的模块、API、页面、组件做定向覆盖，确保新功能被验证、边界与异常被覆盖。典型触发：功能分支合入、需求迭代交付、新增路由/工具/接口上线前。

三者关系：版本对比测试“定位影响面” → 新增功能覆盖测试“验证新东西” → 全量测试“守住整体”；通常组合使用。
