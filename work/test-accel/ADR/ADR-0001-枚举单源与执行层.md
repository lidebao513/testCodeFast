# ADR-0001 枚举单源化与新增独立「执行层」维度

- 状态：已采纳（Accepted）
- 日期：2026-09-10
- 决策人：项目 owner + 本助手

## 背景（Context）

项目在「整体优化」前存在严重枚举散落问题：
- 行为维度（正常/异常/安全/边界）、标签（全量/更新）、来源类型（api/page/ui/business）、
  执行状态（pass/fail/...）、拉取状态（ok/repo_escape_blocked）等枚举字面量散落在
  12+ 个 `.py` 文件，改一处漏九处。
- 来源类型同时有小写 `page/ui` 与大写 `PAGE/UI`（实为 `method` 字段值，非重复但易误删）。
- 「接口」曾被当作「范围关键词（ScopeKeyword）」混入 `resolve_scope` 的 `kinds` 过滤，
  与行为维度 `tp_type` 概念重叠、易误用。
- 缺少「UI 层 / 接口层」执行模式的选择机制，无法支撑"选 UI 但覆盖不了则回退接口层"。

## 决策（Decision）

1. **建立单一枚举真值源**：新增 `backend/core/enums.py`，集中定义
   `TPType` / `Tag` / `FType` / `VerifyLayer` / `Dimension` / `MethodMarker` /
   `ExecStatus` / `PullStatus` 及常量，并内置
   `derive_verify_layer(ftype)` 与 `select_execution_mode(preferred, ftype, ui_available)`。
2. **新增独立「执行层」维度 `VerifyLayer`（接口 / UI）**：
   - 它**不是** `tp_type` 的值（避免与行为维度冲突），也**不是**范围关键词；
   - 每个测试点由 `code_analyzer` 注入 `verify_layer`：`api/business → 接口`，`page/ui/component → UI`；
   - 执行器按所选模式派发，UI 优先但本质接口型或无浏览器时**自动回退接口层**并标记 `layer_fallback`。
3. **移除「接口」范围关键词**：`gen_test_points.resolve_scope` 不再接受"接口"作 scope，
   接口来源筛选能力由 `verify_layer=接口`（= `ftype∈{api,business}`）等价覆盖，不丢覆盖。
4. **保留 `PAGE`/`UI` 大写**：它们是 `method` 字段值（前端产物方法标记），与 `ftype` 小写是两字段，补入 `MethodMarker` 枚举，不删。
5. **门禁强制**：`scripts/check_enums.py` 扫描硬编码枚举字面量（字段感知），pre-commit/CI 拦截。

## 后果（Consequences）

- 正面：枚举改动一处全局生效；执行层可独立演进；回退语义明确；门禁防回归。
- 负面/代价：需 12+ 文件引用改造（已完成）；历史散落脚本未迁移（见 ARCHITECTURE §5，warning 级）。

## 后续约束

- 任何"优化生成"阶段**不得**把枚举重新硬编码回各文件，也**不得**把 `verify_layer` 塞进 `tp_type`
  或重新引入"接口"范围关键词——否则视为违反本 ADR，由 `check_enums` / `check_structure` 拦截。
- 若需新增执行层取值（如"性能层"），在 `enums.VerifyLayer` 扩展并同步 `derive_verify_layer`，
  同时更新本 ADR 与 `CONTRIBUTING.md`。
