# 测试验证任务 · 结构化输入模板

> **用法**：复制下方「任务提交模板」区块，把 `____` 替换成你的实际内容，直接发给我即可。
> 收到后我会：① 按【对比基准】/【任务意图】自动归类测试类型（版本对比 / 全量 / 新增功能覆盖）；
> ② 套用 `report_templates/SCENARIO_WRITING_TEMPLATE.md`（场景区分写作模板）产出报告；
> ③ **默认只规划/生成模板，不执行**——除非你在【附加要求】里明确写"执行测试"。
>
> ⚠️ **凭证安全**：真实账号 / 密码 / 动态口令 / Token 请仅在对话中提供、**不要入库**；
> 本模板与示例中的凭据一律脱敏占位，切勿把明文凭据写进文件或提交到仓库。

## 一、任务提交模板（复制填写）

```
【任务意图】____（验证 / 测试 / 回归 / 扫描）
【代码仓库】____（git URL 或本地路径，如 work/targets/research-agent）
【凭证】____（私有仓库访问令牌 / SSH key 标识；公开仓库可留空）
【分支】____（待测分支）
【对比基准】____（base 分支/版本；版本对比测试必填，其他可留空）
【测试环境】____（线上 URL，或填"本地"）
【账号】____
【密码】____
【动态口令/2FA】____（无则留空）
【待测范围】____（如"代码扫描生成的测试用例，全部在线上对话环境验证"）
【期望产出】____（可勾选：变更摘要 / 测试点 / 用例明细 / 通过失败统计 / 结论与风险 / 复用占比 / HTML报告）
【附加要求】____（如"执行中监控记录""量化复用vs新建占比""仅生成模板，不执行测试"）
```

---

## 二、字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| 任务意图 | 是 | 决定动作：验证=跑+判定；扫描=只识别变更点；回归=围绕修复点；测试=覆盖执行 |
| 代码仓库 | 是 | git 地址或本地 `work/targets/...` 路径 |
| 凭证 | 条件 | 私有仓库必填；公开仓库可省。优先用令牌而非明文密码 |
| 分支 | 是 | 待测分支名 |
| 对比基准 | 版本对比必填 | 有 base→target 的 diff 时才需要；全量 / 新增功能可留空 |
| 测试环境 | 是 | 线上 URL 或"本地" |
| 账号 / 密码 / 动态口令 | 线上验证必填 | 纯本地单测可省 |
| 待测范围 | 是 | 描述覆盖边界，避免"全部/相关"等歧义 |
| 期望产出 | 是 | 列出报告章节，决定产出形态 |
| 附加要求 | 否 | 监控记录 / 量化复用占比 / 是否执行等 |

## 三、场景自动归类（无需手填，按填写特征判定）

| 填写特征 | 归类 | 触发时机（执行时机） |
|---|---|---|
| 有【分支】且【对比基准】不同，且非重大变更 | **版本对比测试** | 多版本差异比对时 |
| 无基准，但【任务意图/附加要求】标注"发布前 / 重大变更" | **全量测试** | 发布前 / 重大变更后 |
| 仅【分支】无基准，标注"迭代新增功能" | **新增功能覆盖测试** | 迭代新增功能时 |

> 判定优先级（冲突时）：重大变更 → 全量；有明确 diff 且无重大变更 → 版本对比；仅增量功能 → 新增功能覆盖。
