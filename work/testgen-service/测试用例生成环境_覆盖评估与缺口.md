## 三、建议补充的功能 / 测试用例方向

### 方向 A：把"生成"补成"验证"（对应 G-1 + G-2，最高优先）
- **接口执行器落地**：`executor.execute_case` 真实发 HTTP 请求，按 `expect`（F8 auth_mode）做五类判定；写操作默认 dry-run。
- **UI 执行器落地**：Playwright 真点按钮/填表单，按 `doc_steps` 的 runtime 细节做可达性/可交互断言（当前如实 skipped）。
- **异步任务 + webhook**：`POST /api/v1/generate` 返回 task_id → 进度 → 完成 webhook；接 testhub + 发布流水线。
- **效果**：用例从"纸面"变"有结论"，覆盖 **正常/安全/边界/异常** 四类可执行判定。

### 方向 B：让安全结论可信（G-3）
- 资源归属识别：扫描接口与业务实体（user/project/thread）的归属关系，越权用例按"他人资源"构造。
- 鉴权态矩阵：匿名/普通用户/管理员 × 公开/可选/必须鉴权 → 预期 401/403/200 精准断言，消除通用模板误报。
- **新增用例方向**：越权访问他人会话/项目、未登录直达受限页、令牌过期续期、权限变更后旧令牌失效。

### 方向 C：异常流与健壮性（G-5）
- **新增 UI 异常测试点**：表单提交失败回显、网络中断重连、超时兜底、空列表/空状态渲染、500 错误页不白屏。
- **新增接口异常测试点**：参数缺失/类型错/超长/注入、429 限流、503 降级、幂等（重复提交）。

### 方向 D：深度发现与多端（G-6 + G-7）
- click-through 穷尽：弹窗/抽屉/Tab/分页/表单提交后视图全覆盖，每个新状态记独立功能点。
- 移动端模拟：Playwright `is_mobile` 视口发现 /m/* 专属交互（底部 Tab、手势、下拉刷新）。

### 方向 E：专项场景（G-8 + G-9）
- 性能/并发：关键读接口（/threads、/agents）的响应时间基线、并发读取不串数据。
- 多租户隔离：跨用户会话/项目/邮件的越权读取与写入防护（贴合 ft.cntaiping 真实风险）。

### 方向 F：工程卫生（G-12~G-15）
- 覆盖率门槛抬到 60%；新增"量级稳定性"集成回归（520 FP 漂移守护）；推送 main、对齐 DEFAULT_SCOPE。
